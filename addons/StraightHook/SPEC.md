# StraightHook: spec

> Jiang Ziya fished with a straight hook, three feet above the water: "the willing fish will bite." A fishing companion in the same spirit as Wuwei: it does nothing for you, and makes what matters audible and visible.

## Problem
The bite is a small splash sound. Music, ambience, NPC chatter, and an alt-tabbed client all bury it, so bites are missed. While fishing, the player also has no idea what this spot yields, how often fish get away at their skill, or what a cast is worth on the AH.

The owner's flow: **Q** casts, **G** (Interact key, soft interact) clicks the bobber on a bite. They don't mouse over the bobber, so information can't live only in a mouseover tooltip.

## Scope
- **In:**
  1. **Sound focus.** While the Fishing channel runs, sound effects go to full and music, ambience and dialog to zero, and sound keeps playing when the client is in the background. Everything is restored shortly after fishing stops.
  2. **Catch log.** Per spot (map + subzone), from fishing loot: items and counts, casts, catches, escapes ("Your fish got away!"), and missed bites (a cast that ended with no loot and no escape).
  3. **Spot info.** Shown on a small movable panel while fishing, and on the bobber's tooltip if moused over. It covers:
     - location;
     - Fishing skill;
     - this spot's catch table (% and count);
     - escape and miss rates;
     - each catch's AH value at Horde and Blackwater, and the expected value per catch;
     - session casts, catches/hour, value/hour.
  4. **Bite probe** (opt-in, `/hook probe`). Records every event during the fishing channel and ranks events that fire just before the player's click. This tests whether *any* bite signal reaches addons on Forever. If one does, v0.2 adds a loud ping on the bite itself.
- **Out:**
  - Auto-clicking or auto-looting the bobber: the click is the player's (and anything else is botting).
  - Pool or node finding.
  - Static loot tables from external sites: tables are learned from your own catches, so they are exact for Forever.
  - Lure tracking: whether Forever's pole is a main-hand weapon or a profession tool is unknown; the probe can find out.

## Secret-value viability (required; see reference/secret-values.md)
All the data is player-only and out of combat. Nothing renders combat data; every read that can be secret is guarded with `issecretvalue`, and then the feature skips that event (no branching on secrets).

## Forever-specific considerations (reference/forever-vs-mainline.md)
- Professions use the Mainline system: Camelot's PaperDollFrame lists `Enum.Profession.Fishing` among the profession-equipment errors, so the pole may be a profession tool. This is why lure tracking is out until the probe shows how lures appear.
- No Blizzard frame is hooked. Tooltips are extended through `TooltipDataProcessor` (Shared code, no Camelot override of GameTooltip in `camelot-overrides.md`).
- No bite event exists in the API docs or the event list (`Events.lua`: no FISH/BOBBER events). The soft-interact events concern target changes, not bites. So the "louder bite" is delivered by sound focus, and the probe checks for an undocumented signal.

## UX
- `/hook` (and `/straighthook`): status and help.
- `/hook sound on|off`: toggle sound focus (default on).
- `/hook panel on|off|reset`:
  - The panel auto-shows on cast and auto-hides 20 s after fishing stops.
  - Drag it to move it; the position is saved; `reset` re-centres it.
- `/hook house 114|117|both`: which AH values to show (default both).
- `/hook probe on|off|report`: the bite-probe experiment.
- `/hook forget here`: clear this spot's log.
- Addon compartment click: same as `/hook`.

## Data model (SavedVariables `StraightHookDB`)
```lua
StraightHookDB = {
  version = 1,
  sound = true, panel = true, house = "both",
  panelPos = { point, x, y },            -- nil = default
  savedCVars = { [name] = value } | nil, -- originals while sound focus is active (crash-safe restore)

            items = { [itemID] = units }, loots = n } },

}
```

## Decisions
- D-001 (2026-11-17): **Separate addon, not a Wuwei module.**
  - Fishing is a different activity and should load and toggle independently.
  - AH values come from its own small generated `Data/Prices.lua` (fish-relevant items only, same part format as Wuwei's), because addon namespaces can't be shared without globals (repo rule 5).
- D-002 (2026-11-17): **Sound focus instead of a bite ping, for now.**
  - The API has no bite event, so a ping can't be timed.
  - Muting competing channels and maximising SFX makes the game's own splash the loudest thing, which is what fishing addons have done since Classic [ANALOG].
  - The probe (scope 4) is the experiment that could unlock a true ping.
  - What breaks if taken literally: if the player changes a volume slider mid-fishing, the restore puts back the pre-fishing value.
- D-003 (2026-11-17): **Learned loot tables only.**
  - Tables are per map + subzone, from the player's own catches.
  - Exact for Forever, empty in a new spot; zone totals fill in until the spot has data.
- D-004 (2026-11-17): **Outcomes per cast.**
  - Each cast ends in exactly one of caught, escaped or missed; early clicks are counted separately.
  - A cast ended by re-casting counts as missed. That's still the useful signal: "how many bites did I not react to".
- D-005 (2026-11-17): **Probe v2: measure from the click, keep raw timelines.**
  - **What went wrong:** the first in-game run (8 casts, Valley of Honor) took "the click" as the moment the verdict ran, 1 s after the channel stop. So the "before the click" window held the click and loot events themselves: `PLAYER_SOFT_TARGET_INTERACTION`, `UNIT_SPELLCAST_CHANNEL_STOP`, `LOOT_READY`, `LOOT_OPENED`, `UNIT_FLAGS`, and skill-ups. All scored 100 % vs 0 % baseline, which says nothing about the bite.
  - **Now:** the click is the first `PLAYER_SOFT_TARGET_INTERACTION` or the channel stop, whichever is earlier. The last 10 casts' event timelines (−12 s … +0.5 s around the click) are kept verbatim in `probe.timelines`, so the bite window can be read by eye.

- D-006 (2026-11-17, owner request: "use publicly available data to fill out the fishing guide"): **Classic prior from an open emulator DB, never from Wowhead.**
  - **Source:** `Data/Seed.lua`, generated by `tools/fishing_seed.py` from `reference/fishing/`. That data is derived from CMaNGOS classic-db (GPL-3.0), with attribution and the licence notes in `reference/fishing/README.md`.
  - **Why not Wowhead:** its robots.txt disallows Anthropic's crawlers by name, and its Forever zone pages have no fishing tab.
  - **What ships:** area IDs, item IDs, shares and base levels only. Area names are resolved in game with `C_Map.GetAreaInfo`, so they always match the client's `GetRealZoneText`/`GetSubZoneText` (subzone first, then zone; Valley of Honor → Orgrimmar).
  - **How it's shown:**
    - Until a spot has `OWN_MIN` (10) catches, the panel shows the Classic table as a prior, labelled "Forever may differ", with prices and an expected value per catch.
    - After that, your table leads and each row shows its Classic share.
    - `≠` marks a significant disagreement: two-sided binomial at about 1 %, with a normal approximation above 60 catches.
    - Classic items you have never caught are listed once the absence is significant.
  - **Skill line:** "no getaways at base + 95". This matches the published thresholds for Durotar/Dun Morogh (25) and Stranglethorn (225); it turns red when your skill plus bonuses is lower.
  - **Breaks if taken literally:**
    - It is the emulator's reconstruction of 1.12, not Blizzard data.
    - Forever adds zones (Zephras Isle) and items the seed lacks.
    - The first comparison (Orgrimmar, 0 Bristle Whisker Catfish in 11 catches where Classic says 30 %) already hints at differences. That is why own data leads and divergences are flagged instead of corrected.
